# insight-faithfulness

檢查語言模型根據多週日誌撰寫自我覺察報告時，引用能否對回原文，以及對「變化」的描述是否有資料支持。

本專案目前完成一輪小型探索實驗：以 3 位虛構人物的 36 篇繁體中文日誌，測試 6 個模型，取得 70 份報告、695 個主張。主要觀察是：模型回傳的 `trend` 標籤，與句子是否描述跨時間變化，可能不一致。例如，GPT-5 在對照人物 Ruby 的基本提示條件下，把 23 個主張中的 21 個標成 `trend`，但沒有句子命中本專案的變化措辭規則。

以下依序說明研究問題、術語、實驗方法、結果與重跑方式。

## 研究問題與適用範圍

自我覺察 App 若要把多週日誌整理成「你最近的心理模式」，需要區分反覆出現的經驗與隨時間發生的變化。「這幾週多次提到自責」只描述重複出現；「自責逐週增加」則需要比較不同週的資料。即使兩句話都附有真實引文，引用也未必足以支持後者的時間方向。

本次實驗比較基本提示與加強引用約束，觀察引文能否在來源中找到，以及模型如何標記、描述跨時間變化。對於能與預先追蹤的主題配對的主張，再用每週關鍵字計數檢查方向是否一致。

本專案將「忠實度」理解為主張受到來源資料支持的程度。目前的自動檢查只涵蓋其中一部分：引文的文字匹配，以及特定主題的方向比對。心理詮釋是否合理、因果關係是否成立，仍需另外判讀。

## 術語與輸出格式

| 術語 | 本專案的定義 |
| --- | --- |
| 主張（claim） | 報告中的一項陳述，以 `claims` 陣列的一筆資料為單位；文字存放在 `text`。 |
| 趨勢主張（trend） | 提示要求以 `type: "trend"` 標記跨時間的變化，例如「自責逐週增加」。這個標籤由模型產生，尚未經驗證。 |
| 單點觀察（point） | 提示要求以 `type: "point"` 標記單一時間點的觀察。現行格式沒有提供「跨時間反覆出現，但未改變」的獨立類別。 |
| 引文與來源 | `quotes` 存放模型引用的原文片段；`entry_ids` 存放模型列出的日誌編號。 |
| 設計表與實際計數 | `data/spec.json` 記錄人物與預定趨勢；`data/journals.json` 的 `counts` 記錄生成後的關鍵字次數。方向評分以實際計數為準。原文件將設計表稱為「真相表」，但它不能保證生成文字完全符合設定。 |

例如，GPT-5 對 Ruby 產出的「因客戶反覆改稿而持續焦慮與不安」被標為 `trend`。這句描述持續的狀態，沒有明說焦慮逐週增加或減少。因此，「被標為趨勢」與「文字宣稱變化」需要分開統計；兩者都不能直接視為已確認的錯誤。

## 實驗方法

### 合成日誌

使用 3 位虛構人物，各 3 週、每週 4 篇，共 36 篇日誌。日誌由 `openai/gpt-oss-120b` 依設計表生成，不使用真人日誌。生成後，程式依指定關鍵字計數。

| 人物 | 生成時的設定 | 生成後可核對的資料 |
| --- | --- | --- |
| 小葳（生科所碩二） | 自責增加，睡眠狀況維持相近 | 自責關鍵字每週為 1、3、4 次；睡眠關鍵字為 3、3、3 次。 |
| 阿哲（工程師） | 與伴侶衝突減少，工作量維持相近 | 衝突關鍵字每週為 3、2、0 次；工作量關鍵字為 2、2、6 次。工作量的設定與詞頻並不一致。 |
| Ruby（接案設計師） | 不安排持續上升或下降的趨勢，作為對照人物 | 睡眠關鍵字為 0、3、0 次，工作量關鍵字為 2、2、0 次。生成資料仍有波動，尚未經人工確認所有主題都沒有趨勢。 |

這些數字是**關鍵字出現次數**。同一事件可能包含多個關鍵字，關鍵字也可能出現在無關情境，例如「怕太吵」會命中衝突詞「吵」。因此，詞頻不能直接當成事件次數、情緒強度或心理狀態的量測。

### 提示條件

兩種條件使用相同的 JSON 格式，都要求模型撰寫 8 至 12 個主張，並提供引用與日誌編號。原先稱為「自由撰寫」的條件仍有格式要求，以下改稱「基本提示」。

| 條件 | 程式代號 | 要求 |
| --- | --- | --- |
| 基本提示 | `free` | 根據三週日誌撰寫報告，依共同格式輸出主張、類型、引文與日誌編號。 |
| 加強引用約束 | `cited` | 額外要求每個主張至少附一段連續、逐字的原文；找不到依據就省略。趨勢主張須引用至少兩篇不同日期的日誌。 |

這裡測的是提示要求的效果。現行評分程式尚未檢查「兩篇不同日期」是否真的滿足，也未逐一驗證引文與 `entry_ids` 的對應。

### 模型與樣本數

| 呼叫服務 | 模型識別碼 |
| --- | --- |
| Groq | `openai/gpt-oss-120b`、`openai/gpt-oss-20b`、`qwen/qwen3.8-27b` |
| OpenAI | `gpt-5`、`gpt-4o`、`gpt-4.1`；資料檔以 `oai:` 前綴識別。 |

原定 3 位人物 × 6 個模型 × 2 種條件 × 2 次重複，共 72 份報告。實際完成 70 份；缺少的是 gpt-oss-120b 對 Ruby 在加強引用約束下的 2 份報告，原實驗紀錄說明為當日額度用完。因此，基本提示有 36 份報告，加強引用約束有 34 份。

各模型的呼叫設定見 [scripts/lib.mjs](scripts/lib.mjs)。例如 GPT-5 未指定溫度，其他模型的報告生成設定為 0.6；這些設定差異也限制了模型間的直接比較。

### 自動評分如何計算

引用與方向評分由 [scripts/score.mjs](scripts/score.mjs) 執行；Ruby 的標籤與措辭統計由 [scripts/control.mjs](scripts/control.mjs) 執行。所有比例都先合計對應範圍內的筆數，再相除。

| 指標 | 計算方式與分母 | 能回答的問題 |
| --- | --- | --- |
| 引文可驗證率 | 通過文字匹配的引文數 ÷ 全部引文數。先移除空白、統一部分標點與移除引號；正規化後至少 6 字，且須出現在同一人物的日誌合併文字中。 | 引用的文字能否在來源中找到。無法確認它是否支持主張。 |
| 無有效引文的主張比例 | 沒有任何引文通過上述檢查的主張數 ÷ 全部主張數。 | 有多少主張缺乏可匹配的引文。 |
| 趨勢標籤比例 | Ruby 報告中 `type` 為 `trend` 的主張數 ÷ 該模型、該條件下 Ruby 的全部主張數。 | 模型多常使用趨勢標籤。 |
| 變化措辭命中率 | Ruby 報告中命中變化詞規則的主張數 ÷ 同一範圍的全部主張數。規則包含「逐漸」「增加」「降低」等詞。 | 有多少句子使用這些措辭。規則可能把一般因果描述也算入，例如「降低焦慮」。 |
| 方向不一致率 | 方向與計數分類不符的主張數 ÷ 可完成方向比對的主張數。分母包含宣稱上升、下降與持平的主張。 | 在可配對主題及方向的子集中，文字方向與詞頻方向是否一致。 |

方向比對先將每個主題的三週計數分為 `up`、`down`、`flat` 或 `noise`。設計數為 a、b、c：上升須滿足 a < b ≤ c，且最大值與最小值至少差 3；下降須滿足 a > b ≥ c，且至少差 3；全距不超過 1 則視為持平，其餘列為 `noise`，不進行方向比對。

接著，程式用關鍵字配對主張的主題與方向。已進入方向檢查、卻無法配對主題、主題屬於 `noise`，或方向不明確的主張，記為 `unclassified`。未命中方向規則、也未標為 `trend` 的主張會略過；它們不算已驗證正確，也不包含在 `unclassified` 中。

## 結果與解讀

以下數字來自儲存於儲存庫的資料，共 70 份報告、695 個主張。結果尚未加入人工語意判讀。

### Ruby：趨勢標籤與變化措辭並不一致

每格依序列出「基本提示／加強引用約束」。分母為對應條件下 Ruby 的主張數，括號內百分比四捨五入至整數。

| 模型 | 趨勢標籤比例 | 變化措辭命中率 |
| --- | --- | --- |
| gpt-oss-120b | 13/21（62%）／無資料 | 6/21（29%）／無資料 |
| gpt-oss-20b | 13/20（65%）／5/18（28%） | 3/20（15%）／1/18（6%） |
| qwen3.8-27b | 15/22（68%）／8/20（40%） | 1/22（5%）／3/20（15%） |
| gpt-5 | 21/23（91%）／17/20（85%） | 0/23（0%）／0/20（0%） |
| gpt-4o | 17/20（85%）／17/19（89%） | 1/20（5%）／0/19（0%） |
| gpt-4.1 | 21/24（88%）／7/23（30%） | 0/24（0%）／3/23（13%） |

GPT-5 在兩種條件下都有超過八成的主張標為 `trend`，但沒有句子命中變化措辭規則。前面的「持續焦慮與不安」就是標籤與文字含義不一致的例子。若產品要依 `type` 呈現「最近的變化」，需要進一步核對時間比較與來源證據。

加強引用約束後，gpt-oss-20b、qwen3.8-27b 與 gpt-4.1 的趨勢標籤比例下降較多。不過，qwen3.8-27b 與 gpt-4.1 的變化措辭命中率同時上升。**減少趨勢標籤，不能直接解讀為減少無依據的主張。**每個模型與條件只有兩次重複，也不足以確定效果是否穩定。

Ruby 的無趨勢設定尚未完成人工驗證，措辭規則也可能誤判。因此，上表呈現的是輸出特徵，不能解讀為「有多少比例的主張已證實是幻覺」。

### 全部人物：引文較常能對回原文

| 條件 | 報告數／主張數 | 引文可驗證率 | 無有效引文的主張比例 |
| --- | --- | --- | --- |
| 基本提示 | 36／362 | 566/668（84.7%） | 18/362（5.0%） |
| 加強引用約束 | 34／333 | 548/601（91.2%） | 12/333（3.6%） |

加強引用約束下，引文可驗證率較高。六個模型中有五個呈現相同方向；gpt-4o 從 89.2% 降至 85.6%，gpt-4.1 在兩種條件下均超過 93%。

這些結果只反映文字匹配。引用確實出現在日誌裡，仍可能與主張無關，或不足以證明跨週變化。此外，兩個條件的樣本組成並不完全相同，不能把合計比例的差異全部歸因於提示。

### 可比對的少量主張：出現方向不一致

| 條件 | 可比對主張數 | 方向一致 | 方向不一致 |
| --- | --- | --- | --- |
| 基本提示 | 21 | 19 | 2/21（9.5%） |
| 加強引用約束 | 12 | 10 | 2/12（16.7%） |

例如，gpt-oss-120b 在加強引用約束下寫出「與伴侶的衝突次數逐漸增加」，但阿哲的衝突關鍵字計數為 3、2、0，與宣稱方向相反。

上述分母只包含能以規則配對主題與方向的主張，且包含持平陳述。合計只有 33 個，占 695 個主張的 4.7%；無法據此估計整份報告的正確率，也不宜用兩個條件的百分比判定哪一種提示較好。

基本提示另有 255 個、加強引用約束另有 165 個主張記為 `unclassified`。其餘 242 個主張未進入方向比對。這些主張的支持程度仍未確認。

## 限制與尚未完成的驗證

本次資料只有三位合成人物、單一語言與固定的報告格式。每個模型與條件預定重複兩次，部分資料缺漏；結果無法直接外推到真人日誌、其他提示或模型版本。

自動評分依賴關鍵字與文字匹配，會漏掉改寫，也可能誤讀語境。引文比對使用同一人物的日誌合併文字，未驗證單篇邊界、來源編號或不同日期的要求。合成日誌本身也有日期不一致的情況，例如 Ruby 第一週正文寫 2023 年，結構化日期欄位則為 2026 年。

下一階段需要人工核對合成資料是否符合設定，並逐項判讀引文對主張的支持程度。現階段尚未完成原設計中的人工三級標註、標註一致性檢查，以及 MiniCheck、NLI、LLM 評分與人工標註的比較。[研究設計文件](docs/superpowers/specs/2026-09-18-insight-faithfulness-design.md)保留的是原始規劃，人物數、樣本數與部分方法尚未按該規劃實作；本 README 描述目前已完成的部分。

## 重現結果

### 使用現有資料重新評分

需要可執行 `.mjs` 的 Node.js。以下指令使用儲存庫中的日誌與報告，不呼叫模型 API，會更新兩份評分 JSON：

```bash
node scripts/score.mjs
node scripts/control.mjs
```

若要重新產生圖表，另需 Python 3 與 Matplotlib。中文標籤需要系統有 `scripts/plot.py` 所列的中文字型。

```bash
python3 -m pip install matplotlib
python3 scripts/plot.py
```

繪圖會讀取 `data/scores.json`、`data/control.json` 與 `data/reports.json`，核對計數與比例後更新 `docs/results.png`。

### 重新呼叫模型

生成完整模型組合需要 Groq 與 OpenAI 的 API 金鑰，並會使用服務額度。程式透過環境變數讀取金鑰：

```bash
export GROQ_API_KEY='你的 Groq 金鑰'
export OPENAI_API_KEY='你的 OpenAI 金鑰'
node scripts/gen-reports.mjs 2
```

`gen-reports.mjs` 會保留 `data/reports.json` 中已有主張的組合，只補跑缺少或失敗的組合。若要重做完整實驗，請先備份並移走既有的 `data/reports.json`，避免新舊報告混用。

若連日誌也要重新生成，在產生報告前執行：

```bash
node scripts/gen-journals.mjs
```

這會覆寫 `data/journals.json`，必須搭配重新生成的報告；不要用新日誌評分舊報告。生成具有隨機性，重新執行不保證得到本頁相同數字。完成後，再執行評分與繪圖指令。
